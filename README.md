# NORD DETAILING

Премиальный демонстрационный сайт вымышленной детейлинг-студии в Таллине. Создан для портфолио VEXORA Digital. Компания, цены, отзывы и адресные данные являются демонстрационными. Реальные услуги не оказываются.

## Запуск

Требуется Node.js 20.9+ (рекомендуется Node.js 22).

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:3000.

```sh
npm run typecheck
npm run build
node scripts/serve.mjs
```

Проект использует статический экспорт Next.js App Router. Готовая сборка находится в `out/`. Команда `next start` для статического экспорта не применяется; используйте `node scripts/serve.mjs` для локальной проверки сборки.

## GitHub Pages

Сайт публикуется по адресу https://stixyrid.github.io/nord-detailing/.
Workflow `.github/workflows/pages.yml` собирает статический сайт и публикует его после каждого push в `main`. В настройках репозитория Pages → Source используется GitHub Actions.

Для проверки такой же сборки локально задайте `NEXT_PUBLIC_BASE_PATH=/nord-detailing` и `NEXT_PUBLIC_SITE_URL=https://stixyrid.github.io/nord-detailing`, затем выполните `npm run build` и `npm start` с тем же `NEXT_PUBLIC_BASE_PATH`. Адрес локальной версии: http://127.0.0.1:3000/nord-detailing/ . Без этих переменных проект по-прежнему собирается для корня домена.

## Развёртывание на Vercel

1. Загрузите проект в свой Git-репозиторий и импортируйте его в Vercel.
2. Framework Preset: Next.js, Build Command: `npm run build`; Vercel распознает статический экспорт.
3. Задайте `NEXT_PUBLIC_SITE_URL` равным фактическому HTTPS-адресу сайта без завершающего слеша. Это обновит sitemap, robots и базовый адрес Open Graph при следующей сборке.
4. Выполните Deploy. База данных, API-ключи и серверные функции не нужны.

Статический каталог `out/` также можно разместить на любом хостинге с поддержкой `index.html` внутри каталогов. `.openai/hosting.json` содержит конфигурацию отдельной демонстрационной публикации Sites; для Vercel она не нужна.

## Страницы и функции

- `/`: полный главный экран, шесть услуг, подход, сравнение, галерея, процесс, образец отзыва, форма.
- `/services/`: подробные описания, состав услуг, ориентировочная длительность и демоцены.
- `/gallery/`: фильтры, полноэкранный просмотр, клавиши ← / → / Escape, сравнение с range-ползунком.
- `/about/`: философия бренда, подход и процесс.
- `/contact/`: демонстрационные контакты, условная карта и форма.
- `/privacy/`: сведения о деморежиме, данных и изображениях.

Переключатель EN / ET переводит интерфейс, услуги и форму. Язык сохраняется в localStorage и применяется после загрузки; исходный HTML и SEO-метаданные на английском. Это не отдельные индексируемые языковые версии. Для полноценного многоязычного SEO можно добавить маршруты `/[locale]/` с серверными метаданными и hreflang.

Словари находятся в `src/lib/content.ts`. Для LV / LT / RU предусмотрен список `plannedLocales`; чтобы добавить язык, создайте полный словарь, расширьте тип `Locale` и список доступных кнопок. Неактивные языки не показываются в интерфейсе.

## Форма и интеграция

Валидация проверяет обязательные поля, email, телефон и дату. `previewBooking` в `src/lib/booking.ts` — граница будущей интеграции: сейчас функция явно возвращает `{ mode: 'demo', submitted: false }`. Она не делает сетевых запросов. Данные существуют только в состоянии React и очищаются после демонстрации; ни localStorage, ни сервер их не получают.

Для реальных заявок подключите серверный endpoint и провайдера доставки, добавьте серверную валидацию, защиту от спама и реальное согласие на обработку данных. Секреты храните только на сервере. При переходе на server-side API уберите `output: 'export'` и используйте серверный деплой Next.js.

## Стек и доступность

Next.js 16, React 19, TypeScript, Tailwind CSS 4, Motion, Lucide. Общие компоненты используют единые токены оформления в `globals.css`. Поддерживаются reduced motion, видимый фокус, skip-link, нативное модальное окно с удержанием фокуса, сенсорный и клавиатурный range-ползунок. Изображения локальные и сжаты; шрифт локальный, внешних запросов в пользовательском интерфейсе нет.

## Проверки

`npm run typecheck` проверяет TypeScript; `npm run build` создаёт производственную сборку всех маршрутов. Браузерный smoke-тест в `scripts/qa.cjs` запускается с установленным Playwright и Chrome, путь к модулю передаётся через `PLAYWRIGHT_MODULE`. Он проверяет страницы, языки, фильтры, lightbox, ползунок, валидацию и мобильное меню. Результаты не заменяют отдельный аудит Lighthouse или проверку на физических устройствах.
